# STACH — восстановление экрана: диагностический этап (v0.1)

**Подтверждено на физической плате пользователя:** заводская программа из резервной копии вернула изображение. Код STACH при запуске на Waveshare 1.43-B показывает только чёрный экран при обоих ранее выбранных профилях SH8601 и CO5300; диагностическая команда D ничего не отображала. Программный флаг `display=1` не означает реального успешного вывода на AMOLED. На старой прошивке I2C ответов также не было.

## Что это за обновление

Добавлен **отдельный временный профиль** `stach-waveshare-bringup`, который НЕ содержит BLE, Wi-Fi или основного STACH UI, а лишь проверяет оборудование и отображает диагностическую картинку. Обычные профили STACH **не изменены**. Цель — прочитать ID контроллера и увидеть, отвечает ли дисплей и периферия при минимальном запуске. После получения результата нужно исправить основной драйвер STACH, не считать v0.1 финальным решением.

1. Сначала выставляется GPIO42 (`AMOLED_EN`) в HIGH, затем запускается I2C на SDA47/SCL48 с подтяжками и выводятся все ответившие I2C-адреса.
2. Выполняется аппаратный дисплейный RESET (только GPIO21), читается регистр `0xDA` по однопроводной SPI-последовательности из примера Waveshare (`0x03 0x00 0xDA 0x00`), отображается прочитанный байт.
3. `0x86` указывает на SH8601, `0xFF` может указывать на CO5300 **или на неответившую подтянутую линию** — это предварительная идентификация.
4. На частоте QSPI 10 МГц выбирается подходящий Arduino_GFX драйвер; принудительно выставляется яркость `255`. Экран циклически показывает **белую заливку**, затем **RGB-квадраты**, затем **два белых глаза**. Эти цвета только для временного теста; дизайн STACH не меняется.
5. Команды USB Serial: `I` повторить I2C scan; `D` повторить цикл картинок.

## Как проверить

1. Сохранить заводской 16 МБ бэкап отдельно и НЕ добавлять его в GitHub.
2. Скопировать изменённые файлы из `STACH-Bringup-Update-Only.zip` **внутрь** `C:\Users\leoni\stach-build` с заменой. Или весь проект `STACH-Bringup-Full.zip` использовать в другой папке без кириллицы.
3. Выполнить в PowerShell из папки проекта: `python -m platformio run -e stach-waveshare-bringup`.
4. В случае SUCCESS и подтверждения версии 1.43-B, закрыть Serial Monitor и прошить: `python -m platformio run -e stach-waveshare-bringup -t upload --upload-port COM3`.
5. После успешной записи открыть Serial Monitor: `python -m platformio device monitor -p COM3 -b 115200`, нажать коротко RESET, сохранить строки `[MEM]`, `[I2C]`, `[LCD-ID]` и `[LCD]`.
6. Прислать вывод и сказать, появились ли белая заливка, RGB-квадраты или глаза. Не публиковать пароли, если они появятся в иных прошивках.

**Не перепрошивать наугад основной STACH, пока результат bring-up не понятен.** Для возврата заводского образа использовать сохранённый полный бэкап по адресу `0x0` только при проверенных происхождении и размере файла. Не запускать `erase-flash`. Если профиль вообще не показывает белый цвет, следующая цель — штатный Waveshare esp_lcd BSP (не бесконечное переключение Arduino_GFX драйверов).

Официальный образец логики ID чтения и GPIO: https://github.com/waveshareteam/ESP32-S3-Touch-AMOLED-1.43/tree/main/examples/arduino/examples/07_LVGL_Test

**Пределы проверки:** примеры производителя подтверждают пины и порядок работы; этот код ещё не скомпилирован в реальном PlatformIO toolchain в авторском окружении и не тестировался на физическом устройстве. `SUCCESS` сборки не доказывает работу экрана.
