# STACH Stage 12 — аппаратная проверка перед первым релизом

**Статус:** НЕ ПРОЙДЕНА. Это чек-лист для проверки НА РЕАЛЬНОЙ ПЛАТЕ, а не журнал уже проведённых испытаний.

## Сначала проверь ревизию

- **Waveshare ESP32-S3 Touch AMOLED 1.43 / 1.43-B:** рассматриваем два существующих профиля SH8601 и CO5300. До прошивки идентифицируй фактический контроллер/ревизию по маркировке, документации и заводскому примеру.
- **Waveshare 1.43C:** текущая прошивка **НЕ ПОДДЕРЖИВАЕТСЯ**. Здесь ESP32-S3-PICO-1-N8R8, 8 МБ Flash, контроллер CO5300 и сенсор CST820; подставлять профиль CO5300 от другой платы недостаточно. Нужен отдельный BSP/распиновка.
- Если платы нет или ревизия неизвестна, **не прошивай наугад**.

## Что понадобится

Waveshare, подходящий USB data-кабель, Windows-компьютер с VS Code и PlatformIO, доступ к Serial Monitor и возможность открыть телефонную панель Stach. Аккумулятор для первых сетевых и экранных проверок не обязателен: начни с питания по USB. Не вскрывай аккумулятор и не замыкай контакты для тестирования. Не роняй устройство намеренно ради проверки датчика падения.

## Подготовка и загрузка через USB

1. Скопируй исходники Stage 12 в свой репозиторий, сделай Commit → Push origin.
2. Дождись зелёных задач `core` и `firmware` в GitHub Actions.
3. **Не прошивай** `stach-network-prototype` на Waveshare в качестве пользовательской версии: это диагностический сетевой профиль без аппаратного интерфейса. В workflow `Stach core checks` скачай артефакт `stach-firmware-<commit SHA>`. Он содержит три комплекта `bootloader.bin`, `partitions.bin`, `firmware.bin` и `MANIFEST.json`/`SHA256SUMS.txt`.
4. Указанные `.bin` **не являются одиночной merged-прошивкой**. Не записывай один `firmware.bin` по адресу 0x0.
5. В VS Code + PlatformIO открой корень `stach` и выбери **только профиль, соответствующий реальной плате**. Для известной платы с SH8601: `pio run -e stach-waveshare-sh8601 -t upload --upload-port COM5` (замени `COM5` на свой порт). Для совместимой ревизии CO5300 — соответствующий профиль. PlatformIO автоматически расставит загрузчик, таблицу разделов и приложение по нужным адресам.
6. Если порт не определяется, сначала проверь USB-кабель и драйвер. Для обычной 1.43 Waveshare рекомендует режим загрузки: удерживать `BOOT`, нажать `RESET`, отпустить `RESET`, затем `BOOT`.
7. После загрузки запусти `pio device monitor -b 115200 -p COM5` и сохрани текст ошибок для диагностики. **Не публикуй лог без удаления пароля Stach Wi-Fi**: исходный код может печатать пароль при старте.

## Честные ограничения на дату релиз-кандидата

- Зеленая GitHub Actions означает **компиляцию и программные тесты**, не гарантию работы конкретного устройства.
- Нет подтвержденного аппаратного сигнала «зарядка активна» — пока нельзя обещать автоматическую радостную зарядную анимацию на настоящем устройстве.
- BAT_ADC не равен автоматическому измерению процента батареи; если схема батарейного канала/калибровка не подтверждена, показывай `?`.
- Включение режима Mouse через BLE требует физической проверки Windows-сопряжения и калибровки гироскопа.
- Полноценный финальный релиз `v1.0.0` выпускать **после приемки**, не до неё.

## Если что-то не работает

- **Экран чёрный:** сначала убедись в точной ревизии (особенно C!), переключи неверно выбранный профиль, сравни с рабочим примером Waveshare; приложи Serial Monitor без пароля.
- **Wi-Fi не появляется:** проверь USB-питание/перезагрузку; изучи Serial Monitor, `GET /api/health` по локальной сети и параметры точки доступа.
- **Сенсор не отвечает:** сравни адрес I²C/распиновку именно твоей ревизии с официальной схемой.
- **BLE виден, но не двигает курсор:** сопряги ПК с `Stach Mouse`, включи Mouse Mode явно, проверь статус подключения и калибровку IMU.
- **Неясный процент зарядки:** не вводи произвольный коэффициент калибровки; оставь индикатор `?` до подтверждения батарейной цепи.
