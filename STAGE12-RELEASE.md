# STACH 12.0.0-rc2 — план релиза

**Важный статус:** RELEASE CANDIDATE / НЕ ПРОШЁЛ АППАРАТНУЮ ПРИЁМКУ.

## Что сделано в Stage 12

1. Непосредственно проверена успешная сборка Stage 11, GitHub Actions run `44074799310`, SHA `32767ec22b60993b8aab2436e427768c4a436b9d` (основа релиз-кандидата).
2. Закреплена платформа `espressif32@8.0.0` и библиотека Arduino_GFX `1.6.9`, с которыми успешно собиралась предыдущая версия; предотвращён автоматический переход на более новую непроверенную версию.
3. Для Waveshare 1.43 / 1.43B уточнены параметры аппаратного профиля: `16MB` Flash, `qio_opi` для 8MB PSRAM; скорректирован 8MB размер флеш-памяти из исходного базового профиля (размер APP-раздела по-прежнему определяется таблицей разделов). **Значения не относятся к 1.43C.**
4. Добавлена генерация пакета артефактов GitHub Actions после каждого успешного запуска: 3 профиля × `bootloader.bin`, `partitions.bin`, `firmware.bin`, контрольные суммы SHA-256 и JSON-манифест.
5. Добавлены автоматические тесты сборщика артефактов; сборщик отказывается создавать пакет, если необходимый `.bin` отсутствует или пустой.
6. Создан пошаговый протокол тестирования железа и инструкция по прошивке без опасного произвольного указания адресов флеш-памяти.

## Как получить .bin без физической платы

Загрузи весь архив Stage12 в свой GitHub Desktop, сделай `Commit → Push origin`, открой вкладку `Actions`, дождись зеленой сборки, нажми на запуск `Stach core checks`. Внизу страницы открой `Artifacts` и скачай `stach-firmware-<SHA>`. Если workflow красный, никакие успешные артефакты релиза не считать валидными; смотри логи.

**Внимание:** сами `.bin` не включены в этот исходный ZIP, потому что для новой конфигурации релиза в этом окружении нет PlatformIO/ESP32 toolchain. В GitHub Actions сгенерируются настоящие файлы после `Push`, а не фиктивные заглушки. `firmware.bin` отдельно нельзя прошивать по адресу 0x0. Рекомендуется загрузка на устройство через USB и PlatformIO по `STAGE12-HARDWARE-TESTS.md`.

## После появления железа

Идентифицируй точную модель. Пройди пункты `STAGE12-HARDWARE-TESTS.md`, сохрани PASS/FAIL и логи без паролей. Поправки по реальному оборудованию могут потребовать изменения драйвера/пинов. Если будет версия 1.43C — потребуется отдельный профиль прошивки.

Финальный тег `v1.0.0` и статус hardware validated не выставлять раньше реальной аппаратной приемки.
